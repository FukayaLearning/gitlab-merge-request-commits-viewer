# GitLab Merge Request Commits Viewer 要求仕様書

## ＜機能要求＞

### Gitコミット解析, 差分取得: 上位要求 R01

**要求**: ローカルGitリポジトリからブランチ情報、時系列コミット一覧（Git TrailersおよびOpenSpecタスクID含む）、およびコミット単位の変更ファイル統計・Unified Diffを取得できるようにする。
**理由**: 1サブタスク＝1コミットで積み上げた変更の意図と差分を、外部ツールに依存せずローカル環境で高速に確認できるようにするため。
**説明**: Python標準ライブラリの `subprocess` を通じて `git` CLI を安全に実行し、構造化されたJSONデータとして提供する。

#### ＜リポジトリ情報・コミット一覧＞

##### 下位要求 R01-01

**要求**: 対象ローカルGitリポジトリの基本情報とブランチ一覧を取得できるようにする。
**理由**: レビュー対象のBase/Headブランチ選択UIの初期値と選択肢を提供するため。
**説明**: 指定されたリポジトリパスが有効なGitリポジトリであることを検証し、メタデータを返す。

###### ＜リポジトリメタデータ取得＞

- □□□ **S01-01-01**: 指定パス（既定 `.`）が有効なGitリポジトリであることを検証し、リポジトリ名、絶対パス、現在のブランチ、全ローカル/リモートブランチ一覧、および既定ベースブランチ候補（`main`, `master`, `develop`, `origin/main`, `origin/master` の優先順）を返却すること。
- □□□ **S01-01-02**: 指定パスが存在しない、またはGitリポジトリでない場合は `GitRepositoryError`（HTTP 400）として明確なエラーメッセージを返却すること。

##### 下位要求 R01-02

**要求**: `base..head` のコミット一覧を時系列順（古い順）に取得し、Git TrailersおよびOpenSpecタスクID・変更種別を自動解析する。
**理由**: コミットの目的（Why/What）・紐づくタスク・実行コマンドを一覧およびサマリカードで構造化表示するため。
**説明**: コミットログ取得後、`viewer_backend/parser.py` にてメタデータを抽出する。

###### ＜コミットログ・メタデータ解析＞

- □□□ **S01-02-01**: `git log --reverse` を用いて `base..head` 範囲のコミットを古い順に取得し、SHA、短縮SHA、件名、本文、作成者名、ISO 8601形式の日時を返却すること。
- □□□ **S01-02-02**: コミット本文から `Issue`, `Task`, `Why`, `What`, `Executed-Command`, `Verification` の各Git Trailersを大文字・小文字を区別せず抽出し、件名・本文・`Task` フィールドからOpenSpec仕様ID（`Sxx-yy` または `Sxx-yy-zz`）を重複なく出現順で抽出すること。
- □□□ **S01-02-03**: `Executed-Command` が `"manual"` 以外かつ空でない場合は `command`、件名が `test:` / `test(...):` に一致する場合は `test`、それ以外は `manual` として変更種別（`change_type`）を判定すること。

###### ＜Diff生成・空白無視オプション＞

- □□□ **S01-03-01**: 指定SHAに対して変更ファイルごとのパス、ステータスコード（`A`/`M`/`D`等）、追加行数、削除行数、バイナリ判定フラグ、およびUnified Diff文字列を返却すること。

### GitLab連携, MR一覧取得: 上位要求 R02

**要求**: GitLab REST API v4を用いて対象リポジトリのオープンMerge Request一覧を取得し、未認証・エラー・オフライン時はローカルブランチ比較へ自動フォールバックする。
**理由**: GitLab上のオープンMRをドロップダウンからワンクリックで選択してレビューできるようにしつつ、オフライン環境やトークン未設定環境でもビューアとして継続利用可能にするため。
**説明**: Python標準ライブラリの `urllib.request` のみを使用し、外部HTTPクライアントライブラリや `glab` CLI への依存を排除する。

#### ＜GitLabプロジェクト解決・API呼び出し＞

##### 下位要求 R02-01

**要求**: ローカルリポジトリの `origin` リモートURLまたは環境変数からGitLabホストとプロジェクトパスを解決できるようにする。
**理由**: ユーザーが毎回プロジェクトIDを手動入力しなくてもGitLab APIのエンドポイントを構築できるようにするため。
**説明**: `gitlab.com` およびセルフホストGitLab（サブグループやSSHポート指定を含む）に対応する。

###### ＜リモートURL解析・環境変数上書き＞

- □□□ **S02-01-01**: `git remote get-url origin` の出力から HTTPS URL（`https://host/group/repo.git`）および SSH URL（`git@host:group/subgroup/repo.git`, `ssh://git@host:port/group/repo.git`）を解析し、GitLabベースURLとプロジェクトパスを自動抽出すること。
- □□□ **S02-01-02**: 環境変数 `GITLAB_URL` および `GITLAB_PROJECT_ID` が設定されている場合、自動抽出結果より環境変数の値を優先して使用すること。

##### 下位要求 R02-02

**要求**: GitLab REST API v4を呼び出してオープン状態のMerge Request一覧を取得する。
**理由**: レビュー対象のMR番号・タイトル・source/targetブランチをUIに提示するため。
**説明**: `PRIVATE-TOKEN` ヘッダーによる認証付きリクエストを実行する。

###### ＜MR一覧APIリクエスト＞

- □□□ **S02-02-01**: `GET {gitlab_url}/api/v4/projects/{url_encoded_project}/merge_requests?state=opened&per_page=50` を実行し、各MRの `iid`（番号）、`title`、`source_branch`、`target_branch`、`web_url` を正規化して返却すること。
- □□□ **S02-02-02**: 環境変数 `GITLAB_TOKEN`（未設定時は `GITLAB_PRIVATE_TOKEN`）が設定されている場合、`PRIVATE-TOKEN` リクエストヘッダーを付与してAPIを実行すること。

###### ＜自動フォールバック＞

- □□□ **S02-03-01**: リモートURL未設定・非GitLabホスト・ネットワーク障害・タイムアウト・HTTPエラー（401/403/404等）・JSON不正・オープンMR 0件のいずれの場合も、`prs`/`mrs` を空配列とし、`fallback: true`、簡潔な `reason`、および既定の `default_base` / `default_head` を返却すること。

### 3ペインレビューUI, サーバー, README: 上位要求 R03

**要求**: ゼロ依存のローカルHTTP/APIサーバー、3ペイン構成の高速レビューWeb UI、およびGitLabトークン権限設定手順を含むREADMEを提供する。
**理由**: `pip install` や `npm install` なしで即座に起動・レビューでき、初回利用者も迷わずGitLab APIトークンを設定できるようにするため。
**説明**: サーバーは `server.py`、フロントエンドは `static/` 配下のVanilla JS + CSS + 同梱Diff2Htmlで構成する。

#### ＜HTTPサーバー・Web UI＞

##### 下位要求 R03-01

**要求**: Python 3標準ライブラリのみで動作するHTTP/APIサーバーを提供する。
**理由**: 任意のローカルGitリポジトリに対して環境構築不要で即座にビューアを起動できるようにするため。
**説明**: CLI引数および環境変数によるリポジトリパス・ホスト・ポート指定をサポートする。

###### ＜サーバー起動・APIルーティング＞

- □□□ **S03-01-01**: `--repo` / `--port` / `--host` CLI引数および `REPO_PATH` / `PORT` / `HOST` 環境変数を解釈し、`ThreadingHTTPServer`（既定 `127.0.0.1:8000`）で起動すること。
- □□□ **S03-01-02**: `GET /api/repo-info`, `GET /api/mrs`, `GET /api/commits`, `GET /api/commits/{sha}/diff` の各JSON APIと、`static/` 配下の静的ファイルを提供すること。

##### 下位要求 R03-02

**要求**: 3ペイン構成のレビューUIとキーボードショートカット・確認済み永続化機能を提供する。
**理由**: マウス操作とキーボード操作の両方でコミット間の切り替えと差分レビューを高速に行えるようにするため。
**説明**: ヘッダー、左ペイン（Commit Menu）、中央・右ペイン（Summary & Diff Viewer）の3領域で構成する。

###### ＜ヘッダー・MR/ブランチ選択＞

- □□□ **S03-02-01**: ヘッダーにリポジトリ名、現在ブランチ、MR選択ドロップダウン（フォールバック時は理由バッジ表示）、Base/Headブランチ選択、Reloadボタンを配置し、MR選択時にBase/Headを自動設定してコミット一覧を更新すること。

###### ＜コミットメニュー・ショートカット・永続化＞

- □□□ **S03-02-02**: 左ペインに時系列コミット一覧、変更種別バッジ（`🤖 Command` / `✅ Test` / `✍️ Manual`）、OpenSpecタスクID、確認済みチェックボックスおよび進捗（`X / Y Reviewed`）を表示し、リポジトリ・SHA単位で確認済み状態を `localStorage` に永続化すること。
- □□□ **S03-02-03**: キーボードの `j` / `↓` で次コミット、`k` / `↑` で前コミット、`r` で選択中コミットの確認済み状態をトグルできること（入力欄フォーカス時は無効化）。

###### ＜サマリカード・Diffビューア＞

- □□□ **S03-02-04**: 中央・右ペイン上部にサマリカード（`Why`, `What`, `Task`, `Verification`, `Executed-Command` 強調表示）を表示し、下部に変更ファイル一覧（クリックで該当Diffへスクロール）、Split / Unified 切替、空白無視（`-w`）切替付きのDiff2Htmlビューアを表示すること。

## ＜非機能要求＞

### 安全性, セキュリティ: 上位要求 R04

**要求**: 外部コマンド実行時のインジェクション防止およびAPIトークンの機密保護を行う。
**理由**: ローカルWebサーバーおよびAPI連携において、不正な入力によるコマンド実行やトークン漏洩を防止するため。
**説明**: 入力バリデーションとシークレット非露出をバックエンド全体で徹底する。

###### ＜コマンドインジェクション対策・シークレット保護＞

- □□□ **S04-01**: `git` サブプロセスは常に `shell=False` の引数配列形式で呼び出し、Git refおよびSHAは許可文字正規表現の検証と先頭ハイフン（`-`）の拒否によりオプションインジェクションを防止すること。
- □□□ **S04-02**: `GITLAB_TOKEN` / `GITLAB_PRIVATE_TOKEN` の値を標準出力、HTTPエラーレスポンス、およびフォールバック理由文字列に一切出力しないこと。
